## 반드시 유지할 장점

기존 v0.4.0은 단순한 쉬운 설명 기법이 아니다. 이름을 현상으로 바꾸고, 독립 모델과 대안 표현을 만들고, 계산·경계 사례·코드·자료로 현실에 닿고, 경쟁 설명과 판별 검사를 만들고, 불리한 증거가 있을 때 전제·범위·결론을 수정하도록 한다. E/P/X 귀속, 선택적 템플릿, 위험별 깊이, 사회·정책 가드레일도 이미 존재한다. 재설계는 이를 새로 발명한 것처럼 포장하지 않는다.

## 원본 코드 기준으로 확인한 결함

### A. 평가자용 자산이 후보 작업 공간에 복사될 수 있다

고정 커밋의 `scripts/run_evals.py`에서 `install_skill()`은 `shutil.copytree(skill_root, target, ignore=...)`로 스킬 루트 전체를 복사한다. 제외 목록은 `__pycache__`, `results`, `review`, `blind-review`, pyc/pyo이며 `evals/`와 `.git/`는 제외하지 않는다. 한편 `evals/reasoning-cases.jsonl`에는 `prompt`와 함께 `expected_findings`, `required_behaviors`, `hard_failures`가 들어 있다.

따라서 후보 프롬프트에 정답을 넣지 않더라도 후보 작업 공간에 평가자 메타데이터가 존재할 수 있다. 이것은 실제 후보가 파일을 읽었다는 증거가 아니라 **읽을 수 있는 경로를 만든다는 결함**이다. `audit/legacy_probes.py`의 합성 최소 재현에서도 eval 파일과 `.git` 파일이 대상에 복사된다.

**개선:** 설치 런타임을 명시적 allowlist로 구성하고 평가 자료를 저장소 경로부터 분리한다. 다만 allowlist 복사만으로 OS·네트워크 격리가 완성되는 것은 아니다.

### B. 실행 행동을 평가하면서 자동 채점 입력에는 trace가 없다

고정 커밋의 `scripts/grade_evals.py`는 실행 결과 디렉터리의 `final.md`를 읽어 `build_judge_prompt(case, candidate)`에 전달한다. 실행 trace는 보존되지만 이 의미 채점 입력에는 포함되지 않는다. 따라서 “실제로 코드를 실행했다”는 주장을 최종 답변만으로 채점할 수 있다.

**개선:** 최종 답변과 evaluator가 확인한 실행·파일·자료 증거를 함께 의미 채점하고, 실행 ID의 신뢰성은 후보가 아니라 evaluator가 제공한다. 현재 `tooling/feynman_grade_gate.py`는 의미 판단을 생성하지 않고 그 판단과 trusted execution ID의 구조적 합격 조건만 검사한다.

### C. 핵심 발견을 모두 놓쳐도 합격 경로가 있다

기존 `validate_and_recompute()`는 필수 행동의 `0`점과 hard failure만 합격 실패에 연결한다. `expected_finding_hit_rate`를 계산하지만 `overall_pass_recomputed`에는 연결하지 않는다. 합성 입력으로 모든 행동을 1점, 모든 기대 발견을 missed, hard failure 없음으로 두면 `general_normalized_score=0.5`, `expected_finding_hit_rate=0.0`인데도 `overall_pass_recomputed=true`가 된다.

이것은 실제 모델의 오답 합격률이 아니라 **결정 함수가 허용하는 상태**를 재현한 것이다.

**개선:** 과제별 필수 발견, 필수 행동의 실질적 충족, 증거 충분성, hard failure를 모두 합격 조건에 연결한다. 어휘 일치가 아니라 동등한 타당 해법은 의미 검토에서 허용한다.

### D. 커밋 식별과 package digest의 경계가 잘못될 수 있다

`run_evals.py`는 `skill_root = Path(__file__).resolve().parents[1]`로 저장소 루트를 구한 뒤, `repository_commit(skill_root)` 안에서 다시 `skill_root.parents[1]`을 Git cwd로 사용한다. README가 설명하는 “저장소 루트가 곧 스킬 루트” 구조와 맞지 않는다. 합성 중첩 저장소에서 바깥 저장소의 커밋을 읽는 경로를 재현했다.

또한 `skill_digest()`는 `.git`를 제외하지 않으므로 설치 런타임이 동일해도 Git 메타데이터 변경만으로 digest가 바뀔 수 있다.

**개선:** 명시한 repository root에서 commit을 읽고, 실제 설치되는 allowlist 파일만 내용 해시로 고정하며 dirty 상태를 별도 기록한다.

### E. “자기비판 후 반드시 무언가 바뀌어야 한다”는 규칙은 반대 편향을 만들 수 있다

기존 스킬은 L2 이상 자기비판이 결론·범위·확신·다음 행동 중 적어도 하나를 바꾸도록 요구한다. 그러나 유효한 검사가 기존 주장을 지지할 수 있다. 파인만의 1973년 인터뷰 전사에서도 알려진 법칙으로 먼저 설명해 보고 지속적으로 실패할 때 변경한다는 태도가 나타난다.

**개선:** 불리한 증거에는 영향을 받은 층을 수정하되, 지지 증거나 새 판별 정보 부재 시에는 결론을 유지할 수 있게 한다. 수정 여부가 아니라 증거와 업데이트의 정합성을 평가한다.

### F. 동일 모델의 다른 표현과 경쟁 모델을 더 분명히 구분해야 한다

파인만의 1948년 *Space-Time Approach to Non-Relativistic Quantum Mechanics*는 익숙한 정식화와 수학적으로 동치인 다른 정식화를 제시한다. 따라서 “다른 표현”에 항상 다른 예측을 요구하면 오히려 잘못이다. 동일 모델의 표현은 동치 조건에서 같은 귀결을 내야 하며, 경쟁 모델은 현재 관찰만으로 식별 불가능할 수도 있다.

### G. 평가 데이터도 단위·분모 검증을 받아야 한다

기존 `abtest-revenue-11`의 기대 발견에서 `1.05 × 0.93 = 0.9765`를 주문당 기대 매출로 부르는 표현이 있다. 주어진 조건에서는 이것이 방문자당 매출 비율이고 주문당 매출은 평균 주문 금액이므로 7% 감소다. 계산 값이 맞아도 관찰량의 이름이 틀리면 평가 기준이 올바른 답을 오염시킨다.

## 재설계의 정체성

새 스킬은 “모든 중요한 문제를 비판하는 범용 비평가”가 아니라 **현상을 작동 모델로 재구성하고 작은 검사로 이해의 빈틈을 드러내는 스킬**로 한정한다.

새 루프는 다음과 같다.

`관찰량 정의 → 최소 모델/다른 표현 → 직접 점검 → 판별 검사 → 증거에 따른 수정 또는 유지 → 정밀함을 보존한 설명`

`quick/standard/deep`은 작업 비용을, `primary/support/off`는 책임 범위를 나타낸다. 인계 계약은 task, scope, claims, checks, decision, revision, open questions를 공유하되 다른 인물의 스킬이 이미 같은 계약을 구현한다고 가정하지 않는다.

## 검증 상태

현재 수행한 것은 공개 개발 사례와 루브릭 작성, allowlist 패키저와 구조적 grade gate 구현, 24개 로컬 단위/회귀 테스트, 구버전 관련 함수의 합성 최소 재현이다. 실제 모델을 동일 조건에서 비교한 행동 평가는 아직 실행하지 않았다. 따라서 새 버전에는 성능 점수나 “검증 완료” 배지를 부여하지 않는다.

원본 `Ronaldony/feynman-thinking` 저장소는 변경하지 않는다. 통합 구현은 `Ronaldony/thinking-skills`의 별도 변경으로 관리한다.
